# Business workspace: operating model and implementation

Updated 6 September 2026. This is a founder workspace implementation, not a claim that Aksen already has a paid client, a full accounting package or a multi-client portal.

## Start with the work that existed before AI

| Business need | Conventional record | AI assistance | Human decision |
|---|---|---|---|
| Know who we are working with | Business file, contact context, project reference | Summarize selected evidence and identify gaps | Confirm identity, relationship and authority |
| Preserve what was learned | Research, call notes, requirements, source documents | Answer questions with source references | Confirm which statements are facts |
| Agree what will be delivered | Proposal, scope, exclusions, acceptance criteria | Prepare drafts from selected source text | Approve prices, promises and scope |
| Request payment | Proforma or invoice register | Check billing readiness against source documents | Review and issue the financial document |
| Record money received | Payment reference, date and receipt | No autonomous money recording | Check payment evidence and record the receipt |
| Deliver and hand over | Project records, handover checklist | Prepare a source-based handover draft | Confirm completion and client acceptance |

The shared record comes first. An agent is a bounded assistant inside the workflow; it does not substitute for identity, state, permissions, accounting arithmetic or approval.

## Implemented

- `/admin/workspaces`, linked as Business files in the existing admin navigation.
- Owner-scoped business records and documents, with optional links to an owned project.
- Text/Markdown import, original-file storage and authenticated downloads. Supported originals: TXT, MD, PDF, DOCX, PNG and JPG, up to 2 MB. PDF/Word/image extraction is not implemented; users supply readable notes for those sources.
- Search by title and text, source-status labels and selection of up to six documents for AI.
- AI discovery briefs, proposals, scope drafts, handover checklists, billing-readiness reviews and source questions. Results are editable and can be saved with source IDs. Sources are treated as untrusted data, not executable instructions.
- An hourly allowance of 20 drafts per admin identity. Document excerpts are bounded to 12,000 characters each. Large selected sources may therefore be incomplete in the model context.
- Financial draft creation and editing, explicit issue, voiding of unpaid records, separate NGN/GHS/USD/GBP/EUR amounts, manually recorded partial or full payments, and linked receipts. Issued documents cannot be edited. No automatic tax rate, exchange conversion or bank reconciliation.
- Server-calculated integer minor-unit totals; unique payment references per invoice; atomic payment, receipt and audit writes. Receipts cannot be independently drafted or generated by AI.
- Printable document and financial previews using the browser’s Print / save PDF flow.
- `/workspace-demo`, linked from Agents, using only a fixed fictional Cedar Studio brief. This is a live AI example with a global allowance of 20 requests/hour. It has no access to real business documents or financial actions.

The source schema is mirrored in Drizzle and `db/workspace-migration.sql`. The migration adds tables without replacing existing business data. File originals are currently stored in Postgres as bounded base64 payloads. Move originals to private object storage with retention and scanning before substantially increasing storage volume.

## Ope’s prospect context

Created a prospect workspace through the authenticated local UI. Imported the existing README, discovery brief, question bank and call guide without modifying Claude’s source files or interactive call task. All imports are labelled unverified. Added a separate evidence-limits note.

The business name is a working label. A shared WhatsApp number does not establish one legal entity. A search that found no website is not proof of absence. Follower counts and one advertised product price do not establish revenue, willingness to pay or Aksen’s proposed fee. No call outcome, signed engagement, price, invoice or payment was invented.

These records belong to the local development identity used by the authenticated preview. Migration to a real production owner identity must be explicit before a deployment is presented as ready for client work.

## Verification

- TypeScript passed during implementation; final verification is recorded in the task response.
- Monetary validation tests: decimal conversion, unsupported precision, negative/scientific-notation amounts, invalid quantities, overflow, invalid dates and leap dates.
- Database regression tests used temporary tables only: partial/full payments, linked receipt/audit records, overpayment rejection, wrong business, duplicate reference rejection and audit-failure rollback. No real financial records changed.
- The live fictional scope preview completed with source reference [1], exclusions and human decisions.
- Prospect documents persisted and reloaded in the authenticated UI. Financial tabs and empty-state forms inspected at 320px; page width measured without horizontal overflow at 320, 375, 390, 430, 768, 1024, 1280 and 1440px. This is browser viewport testing, not physical-device coverage.
- The unauthenticated workspace request was denied. The new production workspace API fails closed when ADMIN_EMAILS is missing; existing unrelated admin routes have not been broadly migrated in this slice.
- Automatic approval review blocked the live test using Ope’s selected discovery brief and evidence note. Specific approval was requested. Those documents were not submitted to the AI service during this review. The fictional test is a separate, permitted payload.
